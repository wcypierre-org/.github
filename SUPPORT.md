# Support

Support for repositories in this organization is best effort.

## Before Opening an Issue

- Read the repository README and setup instructions.
- Search existing issues and pull requests.
- Check for repository-specific support or troubleshooting docs.

## Where to Ask

| Need | Route |
| --- | --- |
| Reproducible application failure | Open a bug report in the owning repository. |
| Failure spanning several services | Open the cross-repository incident form in this repository. |
| Focused capability or usability improvement | Open a feature request in the owning repository. |
| Runner, deployment, or shared-workflow incident | Use the affected infrastructure repository from `REPOSITORIES.md`; use the incident form when ownership is unclear. |
| Repository or organization access | Contact @wcypierre through GitHub without posting private account details. |
| Security vulnerability | Follow `SECURITY.md`; never use a public issue. |

`REPOSITORIES.md` lists the purpose, lifecycle, and support route for active projects. Retired projects direct users to their maintained replacement where one exists.

## Safe Diagnostic Evidence

Include the smallest reproduction, expected and observed behavior, deployed version or commit, and sanitized logs. Remove tokens, passwords, cookies, private keys, personal data, private URLs, and exploit details before posting.

## Funding

This organization is not accepting funding, sponsorships, or paid support requests at this time.

## Repository Overrides

Individual repositories may provide their own support policy. Repository-specific guidance takes precedence over this default file.
